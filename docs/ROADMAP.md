# 서포트랩 구현 우선순위

해커톤 2주 안에 **"공고를 넣으면 → 지원서 뼈대와 업로드 일정이 나오고 → 크레딧이 차감되는"** 한 바퀴를 실제로 돌리는 것이 목표다.
그래서 이 한 바퀴에 꼭 필요한 기능을 P0로, 데이터가 쌓여야 의미가 있거나 외부 승인이 필요한 기능을 뒤로 뺐다.

## 우선순위 표

| 순위 | 기능 (요구사항 번호) | 모듈 | 상태 | 데모에서 |
|---|---|---|---|---|
| **P0** | 회원가입 + 무료 크레딧, 토큰제 | `credits` | ✅ 로직 완료 | 실제 동작 |
| **P0** | 공고 넣기 → 공고 분석(요강 역설계) | `notice` | ✅ 로직 완료 | 실제 동작 |
| **P0** | 2. 지원 양식 뼈대 | `skeleton` | ✅ 로직 완료 | 실제 동작 |
| **P0** | 대시보드: 마감일·업로드 계획 표시 | `planner` | ✅ 로직 완료 | 실제 동작 |
| **P1** | 1. 경향 분석 (팀 수집 시트 집계) | `trends` | ✅ 로직 완료 | 시트 CSV로 실제 동작 |
| **P1** | 6. 합격자 자료 업로드 + 동의 + 검수 + 보상 | `contribution` | ✅ 로직 완료 | 실제 동작 (검수는 관리자 화면) |

| **P1 필수** | 3. 서포터즈 전용 계정 생성 가이드 | `account` | ✅ 로직 완료 | 실제 동작 |

| **P1 필수** | 4. 예약 게시 | `publish` | ✅ 스케줄러 + Graph API 클라이언트 완료 | 팀 본인 계정으로 실제 게시 (개발 모드) |

### 왜 이 순서인가
1. **P0는 외부 의존이 없다.** 공고 분석·뼈대·일정은 규칙 기반으로 돌고, LLM은 보강용이다. API 승인을 기다리지 않아도 된다.
2. **크레딧이 P0인 이유:** 수익 모델이 심사 핵심이라, 차감·적립이 실제로 도는 모습을 보여줘야 한다.
3. **P1은 데이터가 필요하다.** 경향 분석은 팀원 1인당 15건 수집이 끝나야 의미가 있고, 피드백은 인스타 계정 연결(앱 검수)이 필요하다. 로직은 먼저 만들어 두고 데이터가 들어오면 붙인다.
4. **계정 생성·콘텐츠 생성·예약 게시는 필수 기능으로 올렸다.** 영상 편집은 오픈소스 ffmpeg로 서버에서 렌더하고, 예약 게시는 Meta 앱을 개발 모드로 두고 팀원 본인 계정(앱 역할 보유)으로 게시한다. 다른 사용자 계정에 게시하려면 출시 전에 Meta 앱 검수가 필요하다. 설정 방법은 [INSTAGRAM_SETUP.md](INSTAGRAM_SETUP.md).

## 개발 순서 (모듈 → UI → 통합)

1. **모듈 (지금 단계)** — `packages/core`. 화면 없이 테스트로 검증한다. `npm test`
2. **UI (완료)** — `apps/web` (Next.js 15). 모듈을 직접 import 하고 메모리 저장소·데모 LLM·데모 게시로 모든 화면이 동작한다.
3. **통합 (다음)** — Supabase 저장소 구현(`CreditStore` 등 인터페이스 구현체), 관리자 권한, 렌더 파일을 Storage로 이동. 인스타 OAuth·예약 게시 주기 작업 라우트는 이미 있음.

## 팀 분담 제안 (4인 기준)
- A: `apps/web` 대시보드·캘린더 화면
- B: Supabase 연동 (인증, `CreditStore` 구현, 마이그레이션 적용)
- C: 공고 분석·뼈대 프롬프트 다듬기 + 실제 공고 10개로 테스트 케이스 늘리기
- D: 수집 시트 60건 완성 + 합격자 기여·검수(관리자) 화면
